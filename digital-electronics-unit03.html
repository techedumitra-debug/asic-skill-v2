A binary word needs an interpretation

The four-bit pattern 0101 may mean the unsigned integer 5, the BCD digit 5, a Gray-code symbol corresponding to a different binary position, or part of a character encoding. The bits alone do not tell the receiver which interpretation is intended. A coding convention defines the valid patterns, their meanings and any checking rules.

Families of binary codes

A binary code gives a defined meaning to each permitted pattern of zeros and ones. The bits may denote a decimal digit, a character, a sensor position, or protected information sent across a noisy link.

Choosing the correct code depends on the job: compact data representation, decimal display, transitions between positions, or detection and correction of faults.

RELATED TOPIC · NUMERIC ALPHA

Numeric and alphanumeric codes

A numeric code is intended for quantities or decimal digit symbols. A four-bit BCD group describes one decimal digit, not necessarily the value of an entire multi-digit number.

An alphanumeric code additionally represents letters, punctuation and control characters. ASCII uses a seven-bit basic character set; EBCDIC uses eight-bit character assignments.

Digit values are not character values

A numeric digit code assigns a binary pattern to a number from 0 through 9. An alphanumeric code assigns patterns to characters such as A, 7 and ?. For example, decimal digit 7 in 8421 BCD is 0111; the ASCII character 7 is decimal 55, or 0110111 in seven bits.

3.1.2 · Binary codes

Weighted and non-weighted coding

A weighted code gives each bit position a fixed numerical contribution. A 4-bit 8421 word has weights 8, 4, 2, 1; sum the weights of the asserted bits to obtain the digit.

A non-weighted code such as Excess-3 or Gray code cannot be decoded by simply adding positional weights. Instead, it follows its own mapping rule.

The weighted-code rule

In a weighted decimal code, each code-bit position has a fixed coefficient. To decode, multiply each bit (0 or 1) by its coefficient and sum the products. The coefficient sequence must be known; the same bit pattern can represent different digits under different code families.

Digit value = w3b3 + w2b2 + w1b1 + w0b0

Worked example (8421): 0110 represents (0 × 8) + (1 × 4) + (1 × 2) + (0 × 1) = 6. The same four physical bits must be decoded differently if a different table is specified.

RELATED TOPIC · NEGATIVE WEIGHTS

Positive and negative weighted codes

Some decimal coding schemes use only positive coefficients, such as 2421, 5211 and 5421. Other schemes mix positive and negative coefficients, including 84−2−1 and 64 2−3.

When weights are repeated or signed, several bit patterns may sum to the same value; the code table specifies which pattern is chosen.

8421: 0101 → 0·8 + 1·4 + 0·2 + 1·1 = 5

A valid codeword is defined by the coding convention; the arithmetic sum alone does not establish that a bit pattern is permitted.

How negative weights work

A negatively weighted code is decoded by adding positive contributions and subtracting the contributions of asserted negative-weight positions. For 84−2−1, the weights are 8, 4, −2, −1. Its pattern 1010 equals 8 − 2 = 6. The code 0111 equals 4 − 2 − 1 = 1.

3.1.4 · Binary codes

Detection and correction codes

Error detection answers whether a received word violates an agreed check. Error correction uses enough redundancy to locate and repair at least a defined class of faults.

For example, a parity bit can expose an odd number of bit flips. A Hamming code uses multiple parity checks to identify the position of one corrupted bit.

Detection

Parity · checksum · codeword distance

Correction

Hamming syndrome locates an erroneous bit

Why extra bits are transmitted

Stored or transmitted bits can change because of noise, a faulty memory cell or an electrical disturbance. An error-control code adds redundancy so that the receiver can detect unexpected bit patterns and, for a sufficiently strong code, determine the most likely original message.

ApproachCan detect?Can correct?Illustrative limitation

Two-dimensional parityMany multi-bit patternsSome single-bit errorsCertain four-bit rectangles are undetected

ChecksumMany accidental modificationsNoDifferent data blocks can have identical checksums

Error detection is not the same as correction. Detection establishes that a received word violates the code rules; correction requires enough distinct checks to identify which bit or symbol should be changed.

Distance between legal codewords

The minimum Hamming distance between distinct legal codewords determines the guaranteed error capability of a code. A code with minimum distance dmin can detect up to dmin−1 bit errors and correct up to floor((dmin−1)/2) errors, under the usual nearest-codeword decoding assumptions.

Detection ≤ dmin − 1   •   Correction ≤ ⌊(dmin − 1) / 2⌋
Try it: Why can a parity bit detect one flipped bit but not two?

One flip changes the parity of the total number of ones. Two flips leave the overall parity even/odd condition unchanged.

RELATED TOPIC · SEQUENTIAL SELF

Sequential and self-complementing codes

In a sequential code, successive decimal digits are mapped to consecutive binary code values. Natural 8421 and Excess-3 have this property, making ordered sequences easy to recognize.

A self-complementing decimal code has a useful symmetry: complementing every bit of the code for digit d yields the code for 9−d. The XS-3 and 2421 code tables demonstrate this.

Sequential versus self-complementing

A sequential code assigns consecutive codeword values to successive decimal digits, as natural 8421 BCD does for 0 through 9. A self-complementing code has a different property: complementing every bit of the code for d gives the code for 9−d.

For instance, the Excess-3 code of decimal 2 is 0101. Its bitwise complement is 1010, which encodes decimal 7 = 9 − 2. Thus Excess-3 is self-complementing. A code does not become self-complementing merely because its values are arranged in a sequence.

Key takeaway: Sequential ordering and complement symmetry are distinct properties.

RELATED TOPIC · CYCLIC REFLECTIVE

Cyclic, reflective and natural codes

A unit-distance code changes just one bit when moving from one codeword to the next. Reflected Gray code is the classic example, including wraparound between the final and first values.

Reflective generation builds a wider Gray sequence by appending a mirrored copy of the previous sequence. In contrast, natural binary is weighted, and adjacent numbers sometimes change several bits.

Natural binary versus unit-distance order

Natural binary is optimized for arithmetic. At a transition such as 7 (0111) to 8 (1000), four bits change. Reflected Gray code is designed so consecutive codewords differ in only one bit, reducing ambiguous intermediate readings at mechanical sensor boundaries.

3.2 · Binary codes

8421 Binary-Coded Decimal

In 8421 BCD, each decimal digit is represented by one 4-bit group. For instance, decimal 47 becomes 0100 0111, not the seven-bit binary encoding of the number forty-seven.

Only 0000 through 1001 represent decimal digits. Patterns 1010 through 1111 are not valid single BCD digits.

How 8421 BCD represents decimal numbers

The 8421 Binary-Coded Decimal code encodes each decimal digit separately as a four-bit word with weights 8, 4, 2, and 1. For example, decimal 59 is stored as 0101 1001, not 00111011, which is the ordinary unsigned binary representation of fifty-nine.

RELATED TOPIC · BCD ADD

BCD addition and correction

BCD addition begins with ordinary 4-bit binary addition of each decimal digit. If a digit sum exceeds nine or generates a carry, adding binary 0110 moves it past the six unused BCD combinations.

The resulting carry is passed to the next higher decimal digit. This correction is applied separately to each 4-bit digit group.

When a binary sum requires decimal correction

A 4-bit binary adder naturally counts in base 16. BCD digits must count in base 10, so a raw nibble greater than 1001 (9) is not a legal BCD digit. If a raw 4-bit addition produces 1010–1111, or if it generates a carry out of the nibble, add binary 0110 (decimal 6) to perform the BCD correction. The resulting carry becomes the decimal carry for the next digit.

If nibble sum > 1001 or carry-out = 1, add 0110 to the low nibble.

3.2.2–3.2.3 · Binary codes

BCD subtraction and complements

Digit-wise BCD subtraction requires borrow tracking; a borrowed digit may need a subtraction correction of 0110 because the codes above decimal nine are unavailable.

A practical alternative uses the decimal 9’s or 10’s complement of the subtrahend, followed by BCD addition. End-around carry applies to the 9’s complement method; an extra carry is discarded for 10’s complement subtraction.

Decimal complements and BCD subtraction

BCD subtraction can be performed by direct digit-wise subtraction with borrows, or by complement arithmetic. The 9’s complement of an n-digit decimal number N is (10n−1)−N; the 10’s complement is 10n−N. The complemented decimal digits can be encoded in BCD and combined using the BCD-adder correction rules.

9’s complement = (10n − 1) − N    •    10’s complement = 10n − N
MethodEnd carryNo end carry
9’s complementAdd the end-around carry to the retained digitsTake 9’s complement of retained digits and mark negative
10’s complementDiscard the carry beyond n decimal digitsTake 10’s complement of retained digits and mark negative

Worked example: 72 − 38

Using two decimal digits, the 10’s complement of 38 is 100−38=62. Add 72 + 62 = 134. Discard the carry beyond the two-digit result: 34. The corresponding BCD nibbles are 0011 0100. A negative example, 38 − 72, gives the intermediate 38 + (100−72) = 66 with no end carry. Taking the 10’s complement of 66 gives 34; the result is −34.

3.3 · Binary codes

Excess-3 decimal coding

To encode a decimal digit as XS-3, add 3 to the digit and write the result using four bits. Thus, decimal 4 becomes 0111 and decimal 9 becomes 1100.

XS-3 has no positional weights; its ten legal codewords run from 0011 to 1100. Complementing the codeword produces the code of the 9’s complement decimal digit.

Encode and decode with a fixed offset

Excess-3 (XS-3) is a non-weighted four-bit decimal code. It represents decimal digit d by the ordinary four-bit binary encoding of d + 3. To decode a legal codeword, interpret it as unsigned binary and subtract 3. Only the ten patterns from 0011 through 1100 are valid decimal digit codes.

Self-complementing property

Excess-3 provides a useful nine’s-complement property: the bitwise complement of the codeword of digit d equals the XS-3 codeword of digit (9 − d). For instance, XS-3(2) = 0101; invert each bit to get 1010, which is XS-3(7).

NOT(XS-3(d)) = XS-3(9 − d)
Important: Unlike 8421 BCD, the XS-3 bits do not have fixed 8-4-2-1 weights. Do not decode them by adding weights without first removing the offset.
Try it: What is the XS-3 encoding of digit 9?

RELATED TOPIC · XS3 ARITHMETIC

XS-3 addition and subtraction

When adding XS-3 digit groups, an uncorrected binary result must be adjusted by three: with no nibble carry, subtract 0011; with a nibble carry, add 0011 after carrying into the next decimal digit.

For subtraction, complementary XS-3 codewords make 9’s-complement reasoning convenient. At each digit, the adjustment depends on whether the subtraction needed a borrow.

Correcting Excess-3 digit addition

Each encoded digit already contains an offset of +3, so adding two XS-3 digits initially adds an offset of +6. The desired XS-3 result must have only one +3 offset. The correction depends on whether the raw four-bit addition produces a carry.

Example without carry: 2 + 4 = 6. XS-3(2) = 0101 and XS-3(4) = 0111. Raw sum = 1100. Subtract 0011 to obtain 1001, which is XS-3(6).

Example with carry: 8 + 7 = 15. XS-3(8) = 1011 and XS-3(7) = 1010. The raw result is 1 0101. Add 0011 to the low nibble 0101 to get 1000 = XS-3(5); retain a decimal carry of 1, which corresponds to the tens digit.

3.4 · Binary codes

Reflected Gray code

Gray coding is intended to reduce ambiguous readings when a changing position crosses a boundary. Neighboring Gray words differ in only one bit, so a slightly staggered mechanical or electrical transition is less likely to generate a distant reading.

Gray code is not a positional number system for arithmetic. Convert to natural binary before performing ordinary calculations.

Why adjacent Gray words differ by one bit

A reflected Gray sequence assigns bit patterns to successive integer positions so that every adjacent pair differs in exactly one bit. This is useful where multiple sensor lines might not change simultaneously. A conventional binary transition from 0111 to 1000 changes four bits; Gray encoding limits the intended change to one bit at a time.

RELATED TOPIC · GRAY CONVERT

Binary ↔ Gray conversion

Binary-to-Gray conversion keeps the most significant binary bit and XORs each subsequent bit with the binary bit immediately to its left.

To reconstruct binary, keep the leftmost Gray bit; each following binary bit is the XOR of the previously recovered binary bit and the current Gray bit.

Binary to Gray: neighboring-bit XOR

Copy the most significant binary bit to the Gray result. Every remaining Gray bit is the XOR of two neighboring binary bits.

gn−1 = bn−1    •    gi = bi+1 XOR bi

Worked example: B = 1011. Copy 1; then compute 1 XOR 0 = 1, 0 XOR 1 = 1, 1 XOR 1 = 0. The Gray code is 1110.

StepBinary bitsGray bit
MSBb3 = 1g3 = 1
Nextb3 XOR b2 = 1 XOR 0g2 = 1
Nextb2 XOR b1 = 0 XOR 1g1 = 1
LSBb1 XOR b0 = 1 XOR 1g0 = 0

Gray to binary: cumulative XOR

Copy the most significant Gray bit to the binary output, then XOR each following Gray bit with the previously recovered binary bit. This is a prefix-XOR operation.

bn−1 = gn−1    •    bi = bi+1 XOR gi

For Gray 1110, obtain binary bits 1, (1 XOR 1)=0, (0 XOR 1)=1, and (1 XOR 0)=1. Hence binary = 1011, decimal 11.

Try it: Convert Gray 0101 into natural binary.

Start b3=0, then b2=0 XOR 1=1, b1=1 XOR 0=1, b0=1 XOR 1=0. Binary = 0110 (6).

3.5.1 · Binary codes

Parity bits and single-bit detection

A parity bit is added so the combined word has either an even or an odd number of 1s. The receiver recounts the 1s and checks the chosen rule.

An odd number of corrupted bits changes the parity outcome. An even number of flips can escape this simple check, so parity is a detector rather than a corrector.

Generate and verify a parity bit

A parity bit is a single check bit appended to the data so the total number of ones is even (even parity) or odd (odd parity). The transmitter calculates the parity, and the receiver checks the complete received word using the same convention.

Even parity bit = dn−1 XOR … XOR d1 XOR d0
Odd parity bit = NOT(even parity bit)

For data 1011, there are three ones. Even parity requires adding a 1, producing four ones; odd parity requires adding a 0, leaving three ones. If one received data or parity bit flips, the receiver’s parity check fails.

Limits of parity

Parity detects an odd number of bit inversions in the protected word. It does not detect an even number of flips, and it does not identify which specific bit is wrong. Use the interactive parity workbench to flip a data bit and observe the status.

Important: A successful parity check is not proof that the received word is correct; an undetected even number of bit errors is possible.
Try it: Data 0110 contains two ones. What is its odd-parity bit?

1. Adding a 1 makes the complete word contain three ones, which is odd.

RELATED TOPIC · CHECKSUMS

Checksums and data integrity

A checksum summarizes a sequence of data words. The transmitter sends both the data and a check value; the receiver recomputes the check from what it received.

A mismatch indicates corruption, but a matching checksum is not proof that every possible error was absent. The check’s effectiveness depends on its mathematical construction.

Checksum generation and checking

A checksum is a short value calculated from a message or collection of data words. The sender transmits the data together with the checksum. The receiver repeats the calculation and compares it with the transmitted value. A mismatch indicates an error, but a match does not guarantee that no data changed.

A beginner-friendly toy example uses an 8-bit sum modulo 256. For data bytes 0x12, 0x34 and 0x05, the sum is 0x4B. A receiver can recompute the same sum and check whether it equals 0x4B. Modulo-sum checks are easy to implement but have known undetectable changes; different byte sequences can produce the same sum.

RELATED TOPIC · BLOCK PARITY

Two-dimensional block parity

Instead of checking just one word, arrange the data as rows and columns. Add a parity bit to every row and every column.

A single changed data bit violates one row and one column; their intersection identifies the faulty bit. With multiple errors the syndrome can be ambiguous.

Two-dimensional parity example

Two-dimensional parity arranges data bits into rows and columns and appends one parity bit for each row and each column. In the illustrated even-parity case, a flipped data bit makes one row check and one column check fail. Their intersection identifies the suspected bit location.

3.5.4 · Binary codes

Five-bit decimal error-detecting codes

A 2-out-of-5 code uses five positions with exactly two asserted bits for each permitted decimal digit. Any one-bit flip breaks this weight-two rule and can be flagged.

The chapter also describes 63210, Johnson shift-counter and 51111 style code tables. These use different patterns and should not be interchanged without translating the codewords.

2-out-of-5 constant-weight coding

A 2-out-of-5 code has five bit positions and exactly two 1s in every legal decimal-digit codeword. There are C(5,2) = 10 such five-bit patterns, exactly enough to assign one to each decimal digit. A single bit flip changes the number of ones to either one or three and is therefore detectable.

Why codeword validity matters

A code may contain unused bit patterns that serve as a simple error check. With five bits there are 32 possible patterns but only 10 patterns have exactly two ones. Any received pattern with a different number of ones is invalid in the chosen 2-out-of-5 scheme. The workbench demonstrates legal patterns and selected five-bit decimal codes.

Try it: Can a 2-out-of-5 code guarantee detection of any two-bit error?

No. One 1→0 and one 0→1 can produce a different valid two-one pattern, so that error may go unnoticed.

RELATED TOPIC · BIQUINARY

Biquinary coding

Biquinary decimal coding uses seven bits divided into a two-bit group and a five-bit group, with exactly one asserted bit in each group. Therefore a valid codeword contains exactly two 1s.

The high group selects the five-or-zero contribution and the low group distinguishes the remaining digit position. Both subgroup checks help detect invalid received patterns.

Seven-bit grouped decimal representation

A biquinary code divides its seven bit positions into a 2-bit group and a 5-bit group. Exactly one bit in each group is asserted. The 2-bit group represents a choice between the lower and upper five decimal digits; the 5-bit group selects a position within that half.

Using the convention in this lesson, decimal digits 0–4 select the first 2-bit group code 01 and digits 5–9 select 10. The remaining group contains a one-hot selection associated with d mod 5.

RELATED TOPIC · RING COUNTER

Ring-counter codes

In a ring counter, a single 1 circulates through a set of storage elements, creating a sequence of one-hot patterns. The state directly identifies the active position.

A Johnson counter instead circulates an inverted feedback bit, producing a longer sequence of patterns with runs of ones and zeros. The resulting code family is useful for sequencing and simple state decoding.

One-hot ring-counter sequence

An n-stage ring counter circulates one asserted bit through n flip-flops. For five stages, a suitable sequence is 00001 → 00010 → 00100 → 01000 → 10000 → 00001. Exactly one stage is HIGH in each legal state. Ring codes can represent mutually exclusive positions or time slots.

3.6 · Binary codes

Hamming distance and correction capability

The Hamming distance between two equal-length bit strings is the number of positions at which they differ. Minimum distance between valid codewords determines guaranteed detection and correction capability.

A code with minimum distance d can detect up to d−1 bit errors and correct up to ⌊(d−1)/2⌋ errors under the usual nearest-codeword model.

Count the differing bit positions

The Hamming distance d(x,y) between equal-length binary words is the number of bit positions where they differ. XORing the words marks the mismatches; counting ones in the XOR result gives the distance.

d(x,y) = number of 1s in (x XOR y)

Worked example: x = 101101, y = 100011; x XOR y = 001110, which contains three ones. Therefore d(x,y) = 3.

Detection and correction are different guarantees

If legal codewords are at least three bits apart, any single error leaves the received word closer to its original codeword than to any other legal word, enabling single-bit correction. The same code can detect up to two bit errors when used strictly for detection. A plain Hamming code has dmin=3; adding an overall parity bit creates the extended SECDED code used for single-error correction and double-error detection.

Try it: What correction capability follows from dmin = 5?

floor((5−1)/2) = 2 bit errors can be corrected.

RELATED TOPIC · HAMMING74

Hamming (7,4) encoder and error locator

Four data bits occupy positions 3, 5, 6 and 7. Even-parity check bits occupy positions 1, 2 and 4. Each parity check covers positions whose index contains the corresponding power-of-two bit.

At the receiver, the three parity-check outcomes form a syndrome. A nonzero syndrome pinpoints one erroneous bit position, which can then be inverted. This basic code corrects one error; it does not reliably distinguish every possible multiple-error pattern.

Place the four data bits and three parity bits

The conventional even-parity Hamming (7,4) layout numbers positions from 1 to 7 and reserves positions 1, 2 and 4 for parity. Data occupies positions 3, 5, 6 and 7. Each parity bit covers positions whose binary index contains its corresponding 1-bit.

3.6.2 · Binary codes

15-bit Hamming code

For eleven data bits, four parity bits fit at power-of-two positions 1, 2, 4, and 8 in a 15-bit codeword. The same syndrome mechanism can locate one flipped bit.

The number of parity bits r must satisfy 2ʳ ≥ m + r + 1, where m is the number of message bits. For m = 11, r = 4 meets the requirement.

11 data bits + 4 check bits = 15 total bits

Extending the same rule to eleven data bits

The Hamming (15,11) code contains 11 data bits and four parity bits. Reserve codeword positions 1, 2, 4 and 8 for the parity checks; fill the remaining eleven positions with message bits in a consistent declared order.

How the syndrome locates an error

At the receiver, recompute the four even-parity checks. Treat the check outcomes as bits of a binary number S = S8S4S2S1. If S = 0000, no error is indicated; if S is a nonzero value between 1 and 15, it identifies the position of a single assumed flipped bit. For example, syndrome 1010 identifies bit 10.

For SECDED (single-error correction, double-error detection), append one additional overall parity bit to the Hamming code. This produces a 16-bit extended code for 11 data bits and distinguishes common single- versus double-error cases.

Try it: What position is indicated by syndrome 1001?

Binary 1001 equals decimal 9, so a single-error decoder inverts codeword position 9.

RELATED TOPIC · HAMMING128

12-bit Hamming code for eight data bits

Twelve-bit Hamming construction places four even-parity checks at positions 1, 2, 4 and 8 while filling the eight remaining positions with data bits.

The parity checks can locate a single corrupted bit. The basic (12,8) construction does not guarantee simultaneous single-error correction and double-error detection; SECDED requires an extra overall parity bit.

Construct the shortened Hamming (12,8) code

For eight data bits, the inequality 2r ≥ m + r + 1 is satisfied by r = 4, giving 12 total bits. Use parity positions 1, 2, 4, 8; data goes into 3, 5, 6, 7, 9, 10, 11 and 12. This is a shortened Hamming arrangement with the same syndrome principle as the (15,11) code.

For example, syndrome 0111 means codeword position 7. Invert that bit to correct a single-bit error, then extract the eight data positions.

Try it: How many parity bits are required for eight Hamming data bits?

Four parity bits, giving n = 8 + 4 = 12; 2^4 = 16 ≥ 8 + 4 + 1 = 13.

3.7 · Binary codes

Alphanumeric codes and interfaces

Computer terminals, printers and communication links exchange more than numbers. Character codes assign bit patterns to letters, numerals, symbols and certain control operations.

Both ASCII and EBCDIC are character mappings. They are not interchangeable simply because both represent letters. Interoperability depends on a known character-encoding standard.

ASCII

Seven-bit basic character assignments (0–127)

EBCDIC

Eight-bit code family used on some IBM systems

From bit patterns to readable text

Computers exchange messages consisting of characters, not merely numbers. A character encoding maps a character to an integer code value. The sender encodes characters into bytes or bit sequences; the receiver interprets those bytes using the agreed character set and encoding format.

For example, the text string CAT consists of three ASCII characters. Its byte values in hexadecimal are 43 41 54. These values are not the numeric BCD digits 4, 3, 4, 1, 5, 4; they are character codes.

Interoperability and code pages

ASCII and EBCDIC are different character-code conventions. Even when they contain recognizable letters and digits, their numerical assignments are not the same. A system that exchanges text must agree on the mapping; otherwise a receiver may display incorrect symbols.

Modern text commonly uses Unicode with a specified encoding such as UTF-8. For the 128 original ASCII characters, UTF-8 uses the same one-byte values as ASCII. Characters outside that set use multi-byte UTF-8 sequences.

Try it: Why does ASCII character "5" differ from binary number 5?

ASCII "5" is the character code 0x35 (decimal 53). Unsigned binary value five is 00000101 in eight bits.

RELATED TOPIC · ASCII

ASCII character encoding

Standard ASCII maps 128 characters and controls to seven-bit integers. Letters A–Z, a–z, numerals, punctuation and whitespace have fixed values. The same seven-bit assignments are often placed in an eight-bit byte.

For example, capital A has decimal value 65, hexadecimal 41 and seven-bit binary 1000001. A text string is encoded as a sequence of character values, one per symbol.

Seven-bit ASCII character map

ASCII, the American Standard Code for Information Interchange, defines 128 code positions (0–127). It includes uppercase and lowercase letters, decimal digits, punctuation, space and nonprinting control characters such as line feed. RELATED TOPIC · EBCDIC

EBCDIC encoding

EBCDIC (Extended Binary Coded Decimal Interchange Code) uses eight-bit byte assignments and has multiple code pages. Its mapping differs from ASCII even for common letters and digits.

An interchange boundary must decode bytes using the correct EBCDIC code page and then encode the resulting characters into the target format. The page selected below gives standard illustrative mappings for a few digits and capital letters.

Eight-bit EBCDIC and IBM systems

EBCDIC stands for Extended Binary Coded Decimal Interchange Code. It is a family of eight-bit character encodings used chiefly in IBM mainframe and certain legacy environments. Different EBCDIC code pages provide different assignments for some symbols and national-language characters.

Under the frequently encountered IBM code page 037, uppercase A has byte 0xC1, digit 0 has 0xF0, and space has 0x40. Their ASCII byte values are 0x41, 0x30 and 0x20 respectively.

Why translation must use a mapping

A simple bit reversal or arithmetic offset cannot generally convert between ASCII and EBCDIC. Software or hardware must use the correct conversion table for the source and destination encodings. Exchanging raw character bytes without translation may produce unreadable text.

Short VHDL example: 4-bit binary to Gray

library ieee;
use ieee.std_logic_1164.all;

entity bin_to_gray is
  port(b : in std_logic_vector(3 downto 0);
       g : out std_logic_vector(3 downto 0));
end entity;

architecture rtl of bin_to_gray is
begin
  g(3) <= b(3);
  g(2) <= b(3) xor b(2);
  g(1) <= b(2) xor b(1);
  g(0) <= b(1) xor b(0);
end architecture;

All assignments are combinational, so the outputs respond to input changes after the modeled propagation delay. The original interactive VHDL tab on this page also contains the reverse conversion and Hamming encoder.
